# Evidência SDD — TSK-003

**Data:** 06/11/2026

**Branch local:** `feature/TSK-003-loader-documentos`

**Estado:** concluída após revisão humana e correção técnica.

## Intenção e requisitos atendidos

- O JSON `data/base_conhecimento_academica.json` permanece a fonte canônica.
- O loader lê UTF-8 e exige raiz em lista, schema estrito, campos completos e não vazios.
- IDs e fontes seguem `ACAD-NNN`, são únicos, correspondem entre si e formam exatamente `ACAD-001` a `ACAD-012`.
- Cada registro gera uma representação determinística, sem chunks, embedding ou banco vetorial.
- Conteúdo e metadados originais são preservados; o SHA-256 usa os bytes UTF-8 do campo `conteudo`.
- Erros de schema omitem os valores de entrada e identificam registro/campo problemático.

## Planejamento e decisões técnicas

Foram previstos `ingest.py`, um script local, testes temporários, README e esta evidência. Os modelos Pydantic usam `strict=True`, `extra="forbid"` e `frozen=True`. Strings são verificadas com `strip()` apenas para detectar vazio; o valor retornado permanece literal. O texto futuro de embedding usa, deterministicamente, título, categoria e conteúdo. A idempotência de escrita no Chroma permanece fora do escopo e pertence à TSK-004.

Não foram adicionados ChromaDB, FastEmbed, embeddings, busca, Tools, LangGraph ou SQLite. Não houve chamada à Groq.

## Ajuste após revisão técnica

Em 06/11/2026, o loader passou a capturar bytes inválidos durante a decodificação UTF-8 e retornar a mensagem controlada `Arquivo da base não contém texto UTF-8 válido.`, sem conteúdo inválido nem detalhes do decoder. Foi adicionado um teste com arquivo temporário contendo `b"[\xff]"`.

Não houve regressão observada. O commit `76cf838` identifica a implementação inicial; o hash da correção será registrado após sua criação.
