## Decisões técnicas

- Biblioteca padrão `sqlite3`, com `BEGIN IMMEDIATE`, `commit`, `rollback` e fechamento no `finally`.
- Caminhos relativos resolvidos pela raiz do projeto; caminhos absolutos permitidos para testes.
- Fixture: `id=1001`, `tipo=solicitacao_academica_demonstracao`, `status=em_analise`, `origem=seed`, `idempotency_key=seed:SOL-1001`, turma e justificativa nulas.
- Compatibilidade de fixture considera os campos de identidade, mas preserva status e timestamps alterados depois.
- Um ID 1001 incompatível produz `ConflitoFixture` e nenhuma atualização ou exclusão.
- Não foi exposto serviço público de cadastro; escritas de negócio permanecem reservadas à TSK-007.

## Estrutura SQL criada

```sql
CREATE TABLE IF NOT EXISTS solicitacoes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    tipo TEXT NOT NULL,
    turma TEXT,
    justificativa TEXT,
    status TEXT NOT NULL,
    criado_em TEXT NOT NULL,
    atualizado_em TEXT NOT NULL,
    idempotency_key TEXT UNIQUE,
    origem TEXT NOT NULL DEFAULT 'agente'
);
```

Todas as operações com valores usam parâmetros SQL.

## Ajuste final após a revisão

`inicializar_banco()` passou a converter `OSError` de `Path.mkdir()` em `ErroBanco`. A mensagem informa apenas a etapa e o tipo da exceção, sem repetir caminho ou mensagem potencialmente sensível do sistema. O tratamento está antes da conexão e não modifica transação, seed ou a propagação de `ConflitoFixture`.

Foi adicionado teste de regressão que injeta `PermissionError`, confirma a conversão, verifica a sanitização e comprova que nenhum arquivo de banco foi criado.
